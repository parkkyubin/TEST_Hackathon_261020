# REQUIREMENTS.md — 트립메이트 요건·정보 분류 기준

> 트립메이트(여행 일정 변경 대응 AI Assistant)의 요건, 정보 분류(Fact·예보·가정·Unknown·Human check), 제약, 사용자 결정 사항을 정리한 기준 문서다. README와 `docs/DESIGN.md`, `verification/`이 이 문서의 항목 ID(P, F, E, A, U, H, CH/CS, R, S, HB, AP, D-, K 등)를 인용한다.
> 원천 자료 원문은 저장소에 포함하지 않는다. 판정에 쓰는 값은 `sample_input.json`에 출처 ID와 함께 들어 있다.

---

## 0. 출처 ID 체계

| 출처 ID | 의미 |
|---|---|
| `D01`~`D08` | 과제 제공 자료 (여행 일정·예약·이동시간·예보·시설 공지·교통 안내·선호·주의 메모, 자료 기준일 2026-10-10) |
| `REQ` | 과제 요건 (최소 기능, 제출물·README 요건, 실행 가능성 요건) |
| `CALC(…)` | 괄호 안 출처들을 조합한 계산 결과 (§8) |
| `ASM` | 자료에 없어 세운 가정 (§2.3) |
| `USER` | 사용자가 입력·결정한 값 |

> 프로그램이 다루는 모든 입력 값은 `source`(위 출처 ID)와 `kind`(fixed / forecast / estimate / assumption / derived)를 가지며, 출력의 근거 표시는 이 필드에서 자동 생성한다 (R5).

### 설계 원칙 (판단 경계)
| ID | 원칙 |
|---|---|
| CR3 | 자료나 사용자 결정에 없는 값(임계값, 소요시간 기본값, 요금, 가중치 등)은 확정하지 않고 `Unknown` 또는 `Human check`로 남긴다. 입력 파라미터로 노출하되 기본값은 "미정"(null)으로 둔다. |
| CR4 | 핵심 사업성 판단(핵심 문제, 우선순위·트레이드오프, 날씨/지연 임계값, 예산 해석, 추천 정책, 범위)은 사용자가 한다. |
| CR5 | 기술 구현 판단(언어·프레임워크, 파일 구조, 입력 방식, 모듈 분리, 에러 처리)은 구현자가 하고, 결정과 이유를 문서에 기록한다. |
| CR6 | 결정되지 않은 사항은 Unknown(U…, RU…) 또는 Human check(H…)로 남긴다. |
