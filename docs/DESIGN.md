## 1. 처리 흐름: 입력 → 판단/가정 → 결론 → WHY → Human next

| 단계 | 내용 | 산출 객체 |
|---|---|---|
| ① 입력 | sample_input.json 또는 UI 폼. 모든 말단 값은 `{value, source, kind}`. `value: null` = 미정 | `Input` |
| ② 판단/가정 | 규칙 엔진(결정적): P0 역산 → P1 수단 비교 → Soft 경고 → 비판정 항목 분류. 각 판정은 `{id, label(Hard/Soft), status, min_basis, max_basis, sources, assumptions[]}`. 가정은 `USER` 입력값만 허용(엔진이 만들지 않음) | `Judgment[]` |
| ③ 결론 | A: 행동 우선순위(마감 시각순 "무엇을 언제까지") / B: 참고 일정표(범위·미정 칸 그대로) | `Conclusion` |
| ④ WHY | 결론 각 줄의 근거 문장(템플릿+값) + 출처 ID. Unknown은 별도 목록(왜 판정하지 않았는지) | `Why[]`, `Unknown[]` |
| ⑤ Human next | H01~H08 중 해당 항목, 마감 임박순. 각 항목에 판단에 필요한 정보(수치·출처) 동봉(AP4) | `HumanNext[]` |
| (선택) LLM | ②~⑤ 구조화 결과를 한국어로 요약. 판정·수치·순서 변경 금지 | `LlmSummary` |

## 3. 규칙 엔진

### 3.1 P0 — Hard 마감 역산 (승인)
| 단계 | 계산 | 근거 |
|---|---|---|
| B1 | 마감 수집: C 입장 18:40(Hard), O 실내 입장 18:00(Hard, O 포함 시), M 입장창 10:30~11:00·입장 후 120분(Hard, M 포함 시), R 13:00 예약·13:15(Soft, AP3), M 무료취소 09:30(사실·결정기한) | D02 |
| B2 | 최종 출발 = 마감 − 직전 구간 소요. **최대 소요 기준**(= 마감 − max)과 **최소 소요 기준**(= 마감 − min)을 각각 산출 | AP1, D03 |
| B3 | 연쇄: C → O 최종 출발 → P 최종 출발(수단별, §3.2) / R → M 최종 출발 | CH1, CH4 |
| B4 | 상태: `SAFE`(최대 소요로도 충족) / `AT_RISK`(최소만 충족) / `FAIL`(최소로도 미충족) / `UNKNOWN`(필요 값 null 또는 자료 없음) | AP1 |
| B5 | 출발 시각이 입력(USER)된 구간만 상태 판정. 미입력 구간은 "최종 출발 시각"만 제시 | CR3 |
| B6 | 체류시간은 사용하지 않음. USER가 입력하면 보조 표시(참고 일정표 B)에만 사용 | HB4 |

### 3.2 P1 — P→O 이동수단 비교 (승인, 핵심만)
| 단계 | 처리 | 근거 |
|---|---|---|
| T1 | 수단: 지하철, 버스, 택시 (입력 `travel`에 있는 것) | D03, D06 |
| T2 | **점검 겹침 판정(AP2)**: 출발 시각 d에서 평상시 범위로 계산한 이동 구간 `[d, d+max]`가 점검 시간대(입력, 기본 15:00~17:00)와 **1분 이상 겹치면** D06 범위 적용, 아니면 D03 평상시 범위 | AP2, D06 |
| T3 | 평상시 범위가 자료에 없는 수단(점검 시간대 밖 버스·택시)은 `UNKNOWN` | U10 |
| T4 | 수단별 출력: 소요 범위, P 최종 출발(최대/최소 기준), 상태 구간표. **기준 마감 = 전망대 도착 한도 = min(O 실내 입장, C 입장 − O→C 소요)** — 최대 소요 기준은 C − O→C max, 최소 소요 기준은 C − O→C min. 전망대 체류는 미정이라 0분(미포함). 구속 조건과 출처를 함께 표시 | AP1, B3 (검증보고 E-1) |
| T5 | **추천하지 않음**. 비교표 + Human next에 "실시간 지연(H03)·요금/예산(H04) 확인 후 선택" + 판단용 수치 동봉 | AP4 |
| T6 | 택시 사용 횟수 > `taxi_max`(D07)이면 Soft 경고 | D07 |
> U09: 지연이 겹친 시간만큼만 발생하는지 자료 없음 → 겹치면 D06 범위 전체 적용(비례 배분 미적용, 임의 규칙 금지). 결과에 "점검 겹침 → D06 범위 적용(겹침 N분)" 표시.

### 3.3 Soft 경고 · 비판정
| 항목 | 처리 | 근거 |
|---|---|---|
| R 13:15 초과 예상 | Soft 경고 "좌석 미보장" + H07 | AP3 |
| 택시 횟수 | Soft 경고 | D07 |
| 비 올 때 야외 30분 | 예보 사실(시간대·확률·풍속)만 표시, 판정 안 함 → H02, H08 | HB2 |
| 예산 | 판정 안 함 → H04 (요금 미정) | U03, HB6 |
| 21:30 출발 | 판정 안 함 → H06 | U01 |

### 3.4 확정 금지 표현 (R8, D-4)
- 대상: 템플릿 출력 + LLM 출력. 패턴은 D08 예시에서만 도출("반드시 비", "폐쇄됐다", "정확히 N분" 및 동형).
- LLM 출력 위반 또는 결과에 없는 시각·수치 등장 → LLM 요약 폐기, 규칙 기반 출력만 표시.

### 5.1 화면 순서 (위 → 아래, 접기 전 화면에 다섯 블록만)
| # | 블록 | 내용 | 표시 |

| 0 | **상태 배지** | FAIL > UNKNOWN > AT_RISK > SAFE. 판정된 Hard 중 최악값, 판정 불가 Hard가 있으면 UNKNOWN. "Hard 판정 n건 기준 · 판정 불가 k건 · 미판정 m건(사유)" 함께 표시 | 결론 위 (검증보고 E-2) |

### E1. 원본 (D01~D08 그대로, user_times·durations·fares·policy 모두 null)
| 검사 | 기대 | 근거 |
|---|---|---|

| E1-2 | R 13:00 도착을 위한 M 최종 출발 **12:35(최대 소요)/12:40(최소 소요)**, 13:15(Soft) 기준 **12:50/12:55** | CALC(D02, D03) |
| E1-3 | O 최종 출발(C 18:40) **18:10(최대)/18:20(최소)** — Hard, 출처 D02·D03 | CALC(D02, D03) |
| E1-4 | P→O 지하철(O 18:00 기준): 출발 ≤16:45 SAFE, 16:45~17:00 AT_RISK(점검 겹침 → 50~75분), 17:00~17:15 SAFE(평상시 30~45분), 17:15~17:30 AT_RISK, 17:30 초과 FAIL | CALC(D02, D03, D06), AP2 |
