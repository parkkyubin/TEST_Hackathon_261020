## 4. 중대 오류 3건 (P0 관련, 수정 필수)

### E-1 [P0 Hard 역산] P 출발 SAFE 구간이 공연 마감 연쇄를 반영하지 않음
- 재현: `sample_input.json`에서 `deadlines.C_entry.value`를 `"18:00"`, source `USER`로 바꿔 실행 → `actual/oracle/V4_C1800.txt` (UI 폼에서도 동일).
- 현상: KPI·WHY·행동 우선순위·H03이 "P 출발(지하철) SAFE 구간 …17:00~17:15"로 표시한다. 17:15에 출발하면 전망대 도착 17:45~18:00이고, 같은 출력이 요구하는 전망대 최종 출발 17:30을 이미 넘는다. 따라서 **공연(CH1, 최우선 Hard)을 지킬 수 없는 출발 시각을 SAFE로 안내**한다. 기본 입력에서는 18:00(전망대)이 더 이른 마감이라 드러나지 않을 뿐, 역산 체인이 끊겨 있다.
- 수정 방안: P→O 구간표의 기준 마감을 `min(O_indoor, C_entry − O→C)`로 계산한다(O 체류는 미정이므로 0분 + "체류 미포함" 표기). 어느 마감이 구속하는지 출처와 함께 표시한다. 공연 기준 P 출발 구간을 별도 행으로 둬도 된다.

### E-2 [P0 판정 표시] Hard 항목을 판정하지 않았거나 판정할 수 없어도 전체 상태가 SAFE
- 재현 ①: `deadlines.C_entry.value = null` → `actual/oracle/X_null_C.txt`. 결론에 "최종 출발 시각을 계산하지 않았습니다"라고 나오는데도 상단 배지는 `SAFE`다.
- 재현 ②: 기본 입력에서도 실제 도착 판정은 미술관 입장 1건뿐인데 배지가 `SAFE`다(UI 상단, CLI `■ 결론 (SAFE)`).
- 영향: 최우선 Hard(공연)가 UNKNOWN인데 "안전"으로 읽힌다. "불확실한 정보를 확실한 것처럼 말하지 않기"(P03, R8·R9) 위반 소지.
- 수정 방안: 전체 상태 = 판정된 Hard 항목 중 최악값으로 하되, Hard 항목 중 UNKNOWN이나 미판정이 하나라도 있으면 `UNKNOWN`(또는 "판정된 항목 기준 SAFE, n건 미판정")으로 표시한다. CLI 텍스트와 JSON에 같은 규칙을 적용한다.

### E-3 [UI 흐름] "샘플로 초기화"가 폼을 리셋하지 않아 다음 실행에 이전 입력이 섞임
- 재현: UI에서 "공연 입장 마감"을 18:00으로 바꿔 실행 → "샘플로 초기화" 클릭 → 결과는 18:40으로 돌아가지만 **폼은 18:00 그대로** → 다시 "실행"을 누르면 18:00으로 계산된다. 내장 브라우저(Streamlit 1.66.0)에서 재현했다.
- 영향: README ②-3·4의 "입력·결과·폼이 모두 초기화"와 실제 동작이 다르다(S10). 사용자가 변형 입력 후 초기화하면 결과가 오염된다(R10 핵심 흐름).
