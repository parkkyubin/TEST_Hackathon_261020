# 독립 기대결과 — 공통 기준

- 작성: ③ 검증 세션 / **작성 시각 2026-10-20 13:18 (KST)** 착수, 구현 코드·실행 결과 열람 전
- 근거 자료: `docs/REQUIREMENTS.md`(HB1~HB7 반영) + 과제 제공 자료 D01~D08
- 작성 시점의 저장소 상태: `README.md`, `sample_input.json`, `docs/DESIGN.md`, 소스 코드 **모두 없음** → 입력 변경값은 파일 필드명이 아니라 **의미(자료 항목)** 로 기술한다. 2단계에서 실제 입력 형식에 맞춰 매핑하고 그 매핑을 `verification/actual/`에 기록한다.

## 판정 원칙

| ID | 원칙 | 근거 |
|---|---|---|
| J1 | 정답 일정은 하나가 아니다. 정확한 시각이 아니라 **Hard 조건 충족 여부 + 원안·TC0 대비 변화 방향**으로 판정 | P06, REQ |
| J2 | HB2(강수·풍속 임계값), HB3(Hard 판정 max 기준 여부), HB4(체류시간·요금 기본값)는 **미정**. 따라서 프로그램이 이 값을 쓸 때 (a) 입력 파라미터로 노출하고 (b) 출력에 `ASM`/설정값으로 표시하며 (c) 미입력 시 확정하지 않고 Unknown/Human check로 남기는지 확인. 프로그램이 임의 수치를 기본값으로 확정하면 **CR3 위반으로 기록**(결함, Hard 아님) | CR3, CR6, A02~A08, HB2~HB4 |
| J3 | Hard 시간 판정은 **프로그램이 선언한 기준(HB3)과 자기일관적**이어야 한다. 기준과 무관하게 **min ≤ 마감 < max 인 경우 "충족(확정)"으로 표시하면 Fail**(R8: 추정을 확정으로 표현). 이동시간 범위는 항상 병기 | D-3, A05, R8, D08 |
| J4 | "까지" 마감은 **포함(≤)** 으로 해석: 18:40 도착 = 충족, 18:41 = 위반 | D02 원문 "18:40까지" |
| J5 | Pass = 해당 케이스의 모든 필수 항목 충족 / 부분 = Hard(CH·R) 위반 없음 + Soft·표시 항목 일부 누락 / Fail = Hard 위반 1건 이상 또는 실행 불가 | ③ 세션 정의 |
| J6 | 같은 입력을 두 번 실행해 Hard 판정이 같아야 함(LLM 출력 문구 차이는 허용) | D-1, RU1 |

## 금지 표현 목록 (E10 / R8) — 자동 검색 후 문맥 수동 확인

정규식(대략): `반드시 비` · `확실히 (비|온다)` · `비가 온다[.다]` (단정형) · `폐쇄(됐|되었|된 상태)` · `닫혔` · `정확히 \d+ ?분` · `지연(은|이)? \d+분(이다|입니다)` · `틀림없` · `100%` · `21:30.*(출발 가능|문제없)`(확정형)
- 부정·인용 문맥(예: "반드시 비가 온다는 뜻은 아님")은 위반 아님 → 수동 판정.
